# Домашнее задание 2: модель покупателя

Библиотека объединяет товары, позиции, корзину, расчетную цену, состояние баланса и профиль пользователя. `User`, `Contact` и `CommunicationChannel` подключены ссылками на исходные файлы задания 1, без их изменения и копирования. Для сборки нужен стабильный .NET SDK 10.

## Сборка и проверки

Из корня репозитория:

```powershell
dotnet build Homework_2/Homework_2.csproj -c Release
dotnet run --project Homework_2/Tests/Homework_2.Checks.csproj -c Release
```

Проверки работают без сторонних тестовых пакетов. В случае ошибки приложение завершается с исключением и ненулевым кодом. На момент доработки пройдены 94 проверки, сборка Release выполнена с предупреждениями как ошибками.

## Состав

- `Viva/Product.cs` — товар с ценой и названием.
- `Viva/ProductPosition.cs` — позиция товара с количеством.
- `Viva/UserBasket.cs` — корзина, расчет цены, удаление позиций и очистка.
- `Viva/CalculatedPrice.cs` — неизменяемый снимок исходной цены, скидки и итоговой цены.
- `Viola/BalanceState.cs` — неизменяемое состояние денег, бонусов и разрешенной доли оплаты бонусами; поддерживает `with` с проверками.
- `Viola/UserProfile.cs` — пользователь, контакты, корзина, баланс, скидка и история покупок.
- `Tests/Program.cs` — проверки моделей и пример взаимодействия с контрактом оплаты.

`UserProfile` и `BalanceState` расположены в `Marketplace.Domain`, остальные новые модели — в `Marketplace`, как в основе Viva. Вместо отсутствующего `CartItem` профиль теперь использует `ProductPosition`.

## Пример взаимодействия

```csharp
using Marketplace;
using Marketplace.Domain;

var profile = new UserProfile(new User(1, "Иван Иванов", "ivan", "готовый-хэш"));
profile.AddMoney(10000m);
profile.AddBonuses(1000m);
profile.SetPersonalDiscount(0.95m);
profile.SetAllowedBonusRatio(0.1m);

var plate = new Product("Тарелка", 1000m);
var cutlery = new Product("Приборы", 2000m);
profile.Basket.AddPosition(new ProductPosition(plate.Id, 3));
profile.Basket.AddPosition(new ProductPosition(cutlery.Id, 2));
var price = profile.CalculateBasketPrice(new[] { plate, cutlery });
// OriginalPrice = 7000, FinalPrice = 6650, DiscountAmount = 350.

BalanceState before = profile.GetBalance();
BalanceState copy = before with { Money = before.Money + 100m };
// before и баланс профиля не изменились.
```

Для финансовых параметров используйте литералы `decimal` с суффиксом `m`. Прежние методы профиля принимают `decimal` вместо `double`. Денежные значения и доли во всех новых моделях имеют единый тип: исключены неявные смешанные вычисления и значения NaN/Infinity.

## Контракт для сервиса оплаты

Сервис получает `profile.GetBalance()` и `profile.CalculateBasketPrice(products)`. В пределах одного вызова рассчитывает бонусную и денежную части. Бонусами можно оплатить не больше разрешенной доли; если бонусов меньше лимита, остаток оплачивается деньгами. При нехватке денег возвращает отказ без применения нового состояния.

После успешной оплаты сервис сохраняет позиции в историю через `AddPurchases(profile.Basket.GetPositions())`, применяет новое состояние через `ApplyNewBalance` и очищает корзину. Согласованность этой операции, защита от повторной оплаты и проверка принадлежности отдельно переданных корзин — ответственность сервисного класса. В тестах есть простой пример контракта, производственный сервис оплаты в эту доработку не добавлен.

Профиль проверяет свои аргументы, но не дублирует проверки чужих классов. Существование пользователя и товаров, уникальность логинов и каналов и правила округления остаются на уровне соответствующих сервисов. `review_Vi.md` в локальном репозитории не найден; номера пунктов из переписки отдельно не интерпретировались.

## Копирование и ограничения

- ID моделей неизменяемы, количество товара положительно, цена и балансы неотрицательны.
- Профиль создается для пользователя с положительным ID. Несохраненный пользователь с ID = 0 не может иметь корзину.
- Доля оплаты бонусами: от 0 до 0.5. Множитель персональной скидки: от 0.01 до 1; 0.95 означает скидку 5%.
- Проверки `BalanceState` выполняются и в конструкторе, и в `init` при использовании `with`. Значение `default` — нулевой баланс с нулевой бонусной долей.
- Корзина и история копируют позиции на входе и выходе. Изменение исходной позиции или прочитанной истории не изменяет сохраненные данные. Пакет покупок проверяется целиком до добавления.
- Контакты предоставляются через оболочку списка только для чтения. Сами существующие объекты `Contact` остаются ссылочными и изменяемыми.
- Счетчики ID действуют в пределах процесса. Модели рассчитаны на учебное однопоточное приложение, без базы данных и параллельной оплаты.
- Для денег используется `decimal`, промежуточное округление не выполняется. При оплате сервис должен применять единое согласованное правило округления.

Это техническая документация реализации, а не итоговый групповой отчет с полным исходным заданием и составом участников.
