# User и CommunicationChannel

`User` содержит ID, ФИО, логин и готовый хэш пароля. `CommunicationChannel` содержит положительный ID и название канала. Строки ФИО, логина и названия обязательны; крайние пробелы удаляются.

## Изменение пользователя

Для изменения ФИО и логина используйте `ChangeFullName(string)` и `ChangeLogin(string)`. Пустые значения отклоняются, при ошибке прежнее значение сохраняется. ID остается неизменным. Хэш пароля передается готовым и не входит в деконструктор.

## Сравнение объектов

- Пользователи с одинаковым положительным ID равны независимо от ФИО и логина. При ID = 0 пользователь считается еще не сохраненным: равен только самому себе по ссылке.
- Каналы с одинаковым ID равны независимо от названия.
- `Equals` и `GetHashCode` согласованы для `HashSet`, `Dictionary`, `Contains` и `Remove`. Изменение ФИО или логина не меняет хэш пользователя. Оператор `==` не перегружен; для сравнения по ID используйте `Equals` или коллекции.

## Договоренности для сервисного класса

- Уникальность логина среди пользователей проверяет сервис при создании пользователя и перед вызовом `ChangeLogin`. Сам класс проверяет только непустое значение. Правила регистра логина определяет сервис.
- Перед созданием контакта сервис проверяет существование канала с указанным `CommunicationChannelId`.
- Если названия каналов должны быть уникальными, это проверяет сервис; правила сравнения названий также задаются на его уровне.
- Уникальные ID назначает сервис или хранилище. Классы не генерируют ID и не хранят общий список объектов.

Существующий `Contact` не изменяется и связывается с каналом через `CommunicationChannelId`.
